# 모니터링 UI의 조회 범위와 운영 기능

## Concern
초기 모니터링 UI에서 어떤 조회·필터·운영 기능을 제공해야 하는가?

## Status
approved

## Context
- UI의 핵심 목적은 저장된 트래픽 로그를 운영자가 확인하는 것이다.
- 초기 제품은 실시간 스트리밍 모니터링, 알림, 고급 분석보다 기본적인 관찰 가능성을 우선한다.
- 접근 통제 결정에 따라 UI는 localhost에서 제공된다.

## Decision
**Option A — 목록·상세·기본 필터 중심.** 로그 목록, 시간순 정렬, 상태·모델·기간 필터, 페이지네이션, 개별 로그 상세를 제공하고 전문 검색·차트·자동 새로고침·실시간 스트리밍 화면은 후속 범위로 둔다.

## Options
### Option A — 목록·상세·기본 필터 중심
- 로그 목록, 시간순 정렬, 상태·모델·기간 필터, 페이지네이션을 제공한다.
- 개별 로그의 요청·응답·메타데이터 상세를 제공한다.
- Pro: 운영에 필요한 기본 기능과 구현 복잡도의 균형이 좋다.
- Con: 검색·차트·실시간 갱신은 제공하지 않는다.

### Option B — 검색·차트·실시간 갱신 포함
- Option A에 전문 검색, 지연시간·오류 차트, 자동 새로고침을 추가한다.
- Pro: 운영 분석 가치가 높다.
- Con: UI·API·성능 요구사항이 크게 증가한다.

### Option C — 로그 상세 단일 화면
- 최근 로그와 선택한 로그의 상세만 제공한다.
- Pro: 가장 빠른 초기 구현이 가능하다.
- Con: 로그가 많아지면 탐색과 비교가 어렵다.

## Tradeoffs
| | Option A | Option B | Option C |
|---|---|---|---|
| 기본 운영성 | 높음 | 매우 높음 | 낮음~중간 |
| 구현 복잡도 | 중간 | 높음 | 낮음 |
| 초기 범위 적합성 | 높음 | 낮음 | 중간 |
| 확장 기반 | 좋음 | 과함 | 제한적 |

## Recommendation
- 초기 제품에는 Option A를 권장한다.

## Consequences
- 목록·상세·기본 필터·페이지네이션을 UI와 로그 조회 API에 구현한다.
- 전문 검색, 차트, 자동 새로고침, 실시간 스트리밍 화면은 후속 범위로 둔다.
